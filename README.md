# CA Leg Info — Fern Docs (family-400693)

This branch (`arena/01a0bc2b-family-400693`) migrates **every California code section** into **Fern MDX** for the site at `legislature.docs.buildwithfern.com`.

Deployed preview is built by GitHub Actions before every `fern check` / `fern generate`:

```
python3 scripts/generate_fern_sections_mdx.py --clean   # 162,324 MDX pages
```

The repo commits a fast **demo subset** — **FAM (1,636) + CONS (372) = 2,008 MDX** under `fern/docs/pages/codes/sections/` — so PR previews stay quick, while the deployed site has the full corpus.

## How it works (vs. your other repos)

You provided:

- `california-law-ai-corpus` — `BPC.txt`, `FAM.txt`, … with `FAM § N` headers.
- `assistant-ui-template-for-law` + `https-leginfo.legislature.ca.gov` — Astro/Starlight sites with canonical `data/law/*.jsonl.gz` + `export_markdown.py` / `export_html.py`.

This repo keeps the same canonical snapshot (`fern/docs/assets/corpus/law/*.jsonl.gz` + `manifest.json`) **and** adds:

- **One MDX per section** under `fern/docs/pages/codes/sections/<code>/*.mdx` (frontmatter `title`, `description`, `slug: codes/<code>/<id>`, `position`), generated by `scripts/generate_fern_sections_mdx.py` (port of `export_markdown.py` for Fern).
- **One folder in `fern/docs.yml`** so Fern auto-discovers 162k pages without listing them manually:

```yaml
- section: Code Sections (MDX)
  collapsed: true
  contents:
    - page: MDX transfer guide
      path: docs/pages/codes/mdx-transfer-guide.mdx
    - folder: docs/pages/codes/sections
      title: Code Sections
      slug: codes/sections
      title-source: frontmatter
```

See [`fern/docs/pages/codes/mdx-transfer-guide.mdx`](fern/docs/pages/codes/mdx-transfer-guide.mdx) for the full mapping (UID → slug, handling of `CONS:I-1`, duplicates like `FAM:1-2040#2 → 1-2040-2`, hierarchy, `position` ordering, and CI generation).

### Generate locally

```bash
# full 162k
python3 scripts/generate_fern_sections_mdx.py --clean

# single code
python3 scripts/generate_fern_sections_mdx.py --code FAM --clean

# quick test
python3 scripts/generate_fern_sections_mdx.py --code FAM --limit 5
cat fern/docs/pages/codes/sections/fam/1.mdx
```

### Structure

```
fern/docs/pages/codes/sections/
  index.mdx          # catalog of all 30 codes (162,324 sections)
  fam/
    index.mdx        # FAM overview (50 quick links)
    1.mdx            # FAM § 1 → /codes/fam/1
    1-2040.mdx       # UID FAM:1-2040
    1-2040-2.mdx     # UID FAM:1-2040#2 (duplicate)
  cons/
    I-1.mdx          # Cal. Const. art. I, § 1 → /codes/cons/I-1
  gov/
    65913.4.mdx      # etc.
```

Each section MDX has `<Note>`/`<Warning>`, hierarchy, text, history, official LegInfo link (`https://leginfo.legislature.ca.gov/faces/codes_displaySection.xhtml?sectionNum=N.&lawCode=CODE`), and prev/next navigation.

### Catalog vs MDX

- Catalog pages (`fern/docs/pages/codes/*.mdx` — `fam.mdx`, `gov.mdx`, …) remain lightweight overviews for the compressed JSONL. Built by `scripts/build_fern_corpus.py`.
- Per-section MDX is additive, lives under `sections/`, and is what Fern search/Ask Fern indexes for browsing.
- Search UI at `/codes/search` still ranks the JSONL corpus client-side; MDX pages are the click-through targets.

### CI

`.github/workflows/check.yml`, `preview-docs.yml`, `publish-docs.yml`, `publish-fern.yml` all run:

```yaml
- uses: actions/setup-python@v5
- run: python3 scripts/generate_fern_sections_mdx.py --clean
- uses: fern-api/setup-fern-cli@v1
- run: fern check / fern generate ...
```

So the repo can stay small while the site is complete.

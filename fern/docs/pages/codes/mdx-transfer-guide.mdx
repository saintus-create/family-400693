# Transferring Every Code Section to Fern MDX

This guide explains how the full **162,324-section** California Codes snapshot was moved into this Fern site as native **MDX** — while keeping the existing compressed JSONL assets for bulk download and AI indexing.

You mentioned three source repos:

- [`california-law-ai-corpus`](https://github.com/saintus-create/california-law-ai-corpus.git) — plain-text dumps (`BPC.txt`, `FAM.txt`, …) with `FAM § N` headers, hierarchy lines, and `---` separators.
- [`assistant-ui-template-for-law`](https://github.com/saintus-create/assistant-ui-template-for-law.git) — Astro/Starlight site backed by `data/law/*.jsonl.gz` + `data/MANIFEST.json`, with helpers `src/leginfo/export_markdown.py` (one `.md` per section for AutoRAG) and `src/leginfo/export_html.py` (one `.html` per section for crawlers).
- [`https-leginfo.legislature.ca.gov`](https://github.com/saintus-create/https-leginfo.legislature.ca.gov.git) — same Astro stack as above (Cloudflare Pages target), also `data/law/*.jsonl.gz` as the canonical snapshot.

The problem: those outputs are **text / standalone Markdown / HTML**, not **Fern MDX** (frontmatter + `slug` + Fern components). This repo fixes that.

## What "MDX" means in Fern

Every Fern page under `fern/docs/pages/**/*.mdx` needs:

```mdx
---
title: "FAM § 1"
description: "This code shall be known as the Family Code."
slug: codes/fam/1
position: 0
---

# FAM § 1
<Note>Snapshot … Verify at [official LegInfo](…) </Note>
**Code:** Family Code (`FAM`) · **Section:** `1`
## Text
...
```

- `title` → sidebar label when `title-source: frontmatter`
- `description` → SEO / search snippet
- `slug` → final URL (`/codes/fam/1`, not `/codes/sections/fam/1`)
- `position` → statutory order inside a `folder` (otherwise alphabetical)

## Previous approach (why we didn't have 162k MDX before)

`scripts/build_fern_corpus.py` deliberately **did not** create 162k pages:

- One lightweight overview per code (`fern/docs/pages/codes/fam.mdx`, `gov.mdx`, …)
- Full data as compressed JSONL under `fern/docs/assets/corpus/law/*.jsonl.gz` + `manifest.json`
- Client-side search at `/codes/search` and Documents API sync via `scripts/sync_fern_legal_corpus.py`

That kept the repo small and builds fast, but left you without per-section MDX.

## New approach (this branch)

Keep the compressed assets **and** generate optional per-section MDX under a single auto-discovered folder:

```
fern/docs/pages/codes/sections/
  index.mdx                ← overview (slug: codes/sections)
  fam/
    index.mdx              ← per-code index (slug: codes/fam/sections)
    1.mdx                  ← FAM § 1  (slug: codes/fam/1, position: 0)
    2.mdx                  ← FAM § 2  (slug: codes/fam/2, position: 1)
    1-2040.mdx             ← UID FAM:1-2040 → slug 1-2040
    1-2040-2.mdx           ← UID FAM:1-2040#2 → slug 1-2040-2 (duplicate)
  cons/
    I-1.mdx                ← CONS:I-1 (art. I §1)
    II-1.mdx               ← CONS:II-1 (art. II §1)
  gov/
    1.mdx
    7.5.mdx
```

Navigation in `fern/docs.yml` is **one folder**, not 162k `page:` entries:

```yaml
- section: Code Sections (MDX)
  collapsed: true
  contents:
    - folder: docs/pages/codes/sections
      title: Code Sections
      slug: codes/sections
      title-source: frontmatter
```

Fern auto-discovers every `*.mdx` inside, sorts by `position` (statutory order), and uses `index.mdx` as the folder overview. Individual page `slug` frontmatter gives you citation-friendly URLs (`/codes/fam/1`).

## Mapping from the other repos

| Source | Field | Fern MDX |
| --- | --- | --- |
| `*.txt` header `FAM § 2040` | `citation` | `title: "FAM § 2040"` + `# FAM § 2040` |
| `data/law/*.jsonl.gz` `uid` e.g. `FAM:1-2040#2` | `uid` | `file: 1-2040-2.mdx` → `slug: codes/fam/1-2040-2` via `clean_section_slug()` |
| `article` + `section` for CONS | `CONS:I-1` | `cons/I-1.mdx` → `/codes/cons/I-1` |
| `path` / `division` `>` `article` | `hierarchy` | **Location:** breadcrumb in body |
| `text` | `text` | `## Text` |
| `history` | `history` | `## History` |
| `repealed` | badge | `<Warning>` vs `<Note>` |
| `ordinal` | `position` | frontmatter `position: 250` |

The text/markdown helpers in the other repos (`export_markdown.py` → `# CITATION / **Code:** … / ## Text`) were ported to Fern frontmatter + components, and HTML (`export_html.py`) was not needed — Fern renders MDX.

## Script: `scripts/generate_fern_sections_mdx.py`

Port of `export_markdown.py` for Fern, reading the same canonical `fern/docs/assets/corpus/law/*.jsonl.gz`:

```bash
# all 30 codes — 162,324 MDX files (~250 MB, ~3 min)
python3 scripts/generate_fern_sections_mdx.py --clean

# single code (what this branch commits as a demo: FAM + CONS = 2,008 files)
python3 scripts/generate_fern_sections_mdx.py --code FAM --code CONS --clean

# quick test (3 files)
python3 scripts/generate_fern_sections_mdx.py --code FAM --limit 3

# full corpus but only first 10 per code (demo for every code, ~300 files)
for code in CONS BPC CIV CCP COM CORP EDC ELEC EVID FAM FIN FGC FAC GOV HNC HSC INS LAB MVC PEN PROB PCC PRC PUC RTC SHC UIC VEH WAT WIC; do
  python3 scripts/generate_fern_sections_mdx.py --code $code --limit 10
done
```

The script:

- Validates against `fern/docs/assets/corpus/manifest.json`
- Sorts by `ordinal` for statutory order
- Sanitizes `uid` → `file_slug` (`#` → `-`, illegal chars → `-`, collapse `--`)
- Writes frontmatter (`title`, `description`, `slug`, `position`) + body (`<Note>`/`<Warning>`, hierarchy, text, history, metadata, prev/next links)
- Writes per-code `index.mdx` (first 50 links) and root `sections/index.mdx`

Check:

```bash
python3 scripts/generate_fern_sections_mdx.py --code FAM --limit 1
cat fern/docs/pages/codes/sections/fam/1.mdx
```

## CI integration (so you don't commit 162k files)

This branch commits **FAM (1,636) + CONS (372) = 2,008 MDX** as a working demo so `fern check` passes in preview without waiting for full generation. The workflows generate the full corpus transiently before every build:

```yaml
# .github/workflows/check.yml  (and preview-docs / publish-docs / publish-fern)
- uses: actions/setup-python@v5
- run: python3 scripts/generate_fern_sections_mdx.py --clean
- uses: fern-api/setup-fern-cli@v1
- run: fern check   # or fern generate --docs --preview / --docs
```

That keeps the Git repo small while the **deployed site** still has every section as MDX. If you prefer to commit all 162k files, just run the script locally and push — no workflow change needed (but expect a ~250 MB checkout).
